客户端删除项目或任务时，只需提交资源 ID，不传递 `expected_revision`，也不需要先获取最新版本。服务端检查当前账号的访问权限。项目删除由服务端协调停止；单 Task 删除仍要求该任务没有活动轮次。停止尚未确认时保留数据，客户端显示具体原因并允许重试项目 DELETE。

## 删除请求

两个接口均需要登录鉴权，无请求体。项目 ID 和任务 ID 是不透明字符串，客户端应原样保存，构造 URL 时编码。

| 操作 | 请求 | 删除范围 |
| --- | --- | --- |
| 删除任务 | `DELETE /api/project-tasks/{task_id}` | 指定任务及其全部会话轮次、已发布附件、工具记录和上下文。支持项目内和无项目任务。 |
| 删除项目 | `DELETE /api/projects/{project_id}` | 指定项目及其全部 Task，包括已归档任务、会话轮次、附件、工具记录和上下文；活动轮次先停止并确认退出。 |

删除任务示例：

```http
DELETE /api/project-tasks/task_example HTTP/1.1
Authorization: Bearer <token>
Accept-Language: zh-CN
```

删除项目示例：

```http
DELETE /api/projects/proj_example HTTP/1.1
Authorization: Bearer <token>
Accept-Language: zh-CN
```

成功返回 `204 No Content`，响应体为空，并带有 `Cache-Control: no-store`。客户端不要对成功响应调用 JSON 解析。

## 禁止删除的原因

| HTTP 状态 | 错误码 | 原因 | 客户端处理 |
| --- | --- | --- | --- |
| 409 | `TASK_BUSY` | 单 Task 删除的目标仍有活动轮次。 | 提示等待完成或先停止任务，保留任务和会话；这不表示项目删除也要求用户逐个停止。 |
| 409 | `PROJECT_TASKS_BUSY` | 项目删除已请求停止，但执行尚未确认退出、停止超时或存在未知执行结果。 | 保留项目及全部任务记录，提示稍后重试同一项目 DELETE；不能把取消回执当作删除成功。 |
| 404 | `NOT_FOUND` | 资源已不存在，或不属于当前账号。 | 提示资源不存在或无法访问，刷新对应列表。 |

任务删除被拒绝时的响应示例：

```json
{
  "error": {
    "code": "TASK_BUSY",
    "message": "任务正在排队或执行，请等待完成或先停止任务后再操作。",
    "details": {}
  }
}
```

项目停止尚未完成时，错误码为 `PROJECT_TASKS_BUSY`。该错误也用于归档项目时发现活动任务，当前中文消息为：

> 项目中仍有未结束的活动任务，请等待任务停止后重试。

错误处理按 `error.code` 判断；用户提示展示本地化后的原因和处理方式，不只显示“删除失败”或“409”。服务端沿用现有语言解析规则，优先使用已保存的用户语言，其次使用 `Accept-Language`，支持中文和英文。

## 客户端交互

1. 删除前展示确认框。删除项目须明确说明会停止活动任务并永久删除项目、全部任务及历史附件，无法恢复；服务端和客户端工作目录中的文件保留。希望保留历史时可选择归档。
2. 项目删除按钮不因活动任务而禁用，由服务端协调停止；提交期间显示处理中并避免重复点击。单 Task 删除按钮仍在该任务有活动轮次时禁用，提示等待或先停止。
3. 收到 `PROJECT_TASKS_BUSY` 时显示停止尚未完成，保留整个项目和全部会话，允许用户稍后重试 DELETE。只收到取消请求回执或 `cancel_requested=true` 不代表停止，更不代表删除成功。删除处理已持久阻止该项目的新执行，重试不能绕过该保护。
4. 单 Task 删除仍须等待 `active_turn_id=null`；`TASK_BUSY` 不改变该限制。项目归档也仍要求先停止全部活动任务，不会自动执行删除流程。停止协议见[任务 WebSocket 接入指南](project-task-websocket.md)。
5. 仅收到 204 后移除项目及其全部任务列表项；如果正在查看被删除的任务，则关闭对应会话并清除该项目的待发队列。删除标记应拦截迟到分页和会话事件，避免已删除项重新出现。同步规则见[项目和任务增量同步说明](project-task-incremental-sync.md)。

## 数据范围和版本规则

项目删除先持久阻止该项目的新执行，再在数据库事务外请求并等待活动轮次退出；确认停止后，在同一删除事务内清理全部关联 Task 和项目，并记录项目及每个 Task 的同步删除事件。停止未确认不执行部分删除，已经发出的取消请求仍然有效。删除项目后，其单项目列表接口返回 404；全局 Task sync 和项目 sync 提供对应删除标记。

单 Task 删除不影响所属项目、其他任务或独立分支。项目删除也不删除位于其他项目或无项目范围的独立分支，分支已经复制的附件仍可读取。

绑定已删除项目或目标 Task 的定时任务会被禁用，并阻止自动和手动运行，避免引用置空后改成无项目执行；需显式重新选择目标配置后才能再次运行。旧来源映射保留删除墓碑，未受理输入和未发出的投递不会重新生成已删除会话。

删除保留服务端和客户端工作目录中的文件，包括自动分配的任务工作区，不回滚已执行工具的副作用，也不删除专家记忆。已归档项目及其中已归档 Task 同样可被项目 DELETE 清理；删除后的再次读取或再次删除返回 404。

删除接口不要求版本参数。项目编辑、归档或恢复，以及任务改名、归档或恢复，仍须传递 `expected_revision`；切换专家/行动模式还须提供 `expected_configuration_revision`。完整接口参考见 [API 文档](api.md)。
