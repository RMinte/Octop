# 项目和任务删除接口接入说明

更新日期：2026 年 10 月 23 日。统一会话后，项目删除仅适用于空项目，有记录时使用归档。

客户端删除项目或任务时，只需提交资源 ID，不再传递 `expected_revision`，也不需要先获取最新版本。服务端仍检查当前账号的访问权限和任务执行状态。删除被禁止时，客户端应展示具体原因和处理方式，并保留原有列表及会话。

## 删除请求

两个接口均需要登录鉴权，无请求体。项目 ID 和任务 ID 是不透明字符串，客户端应原样保存，构造 URL 时编码。

| 操作 | 请求 | 删除范围 |
| --- | --- | --- |
| 删除任务 | `DELETE /api/project-tasks/{task_id}` | 指定任务及其全部会话轮次、已发布附件、工具记录和上下文。支持项目内和无项目任务。 |
| 删除项目 | `DELETE /api/projects/{project_id}` | 仅删除指定空项目；项目内仍有任何任务记录时拒绝，建议归档。 |

删除任务示例：

```http
DELETE /api/project-tasks/task_example HTTP/1.1
Authorization: Bearer <token>
Accept-Language: zh-CN
```

删除项目示例：

```http
DELETE /api/projects/proj_example HTTP/1.1
Authorization: Bearer <token>
Accept-Language: zh-CN
```

成功返回 `204 No Content`，响应体为空，并带有 `Cache-Control: no-store`。客户端不要对成功响应调用 JSON 解析。

## 禁止删除的原因

| HTTP 状态 | 错误码 | 原因 | 客户端处理 |
| --- | --- | --- | --- |
| 409 | `TASK_BUSY` | 该任务仍有排队或执行中的轮次。 | 提示等待完成或先停止任务，保留任务和会话。 |
| 409 | `PROJECT_TASKS_BUSY` | 项目中至少一个任务仍有排队或执行中的轮次。 | 提示等待完成或先停止所有活动任务，保留整个项目和全部任务。 |
| 409 | `PROJECT_HAS_TASKS` | 项目仍有会话记录，包括已归档记录。 | 提示归档项目保留历史，不自动删除其中任务。 |
| 404 | `NOT_FOUND` | 资源已不存在，或不属于当前账号。 | 提示资源不存在或无法访问，刷新对应列表。 |

任务删除被拒绝时的响应示例：

```json
{
  "error": {
    "code": "TASK_BUSY",
    "message": "任务正在排队或执行，请等待完成或先停止任务后再操作。",
    "details": {}
  }
}
```

项目删除被拒绝时，错误码为 `PROJECT_TASKS_BUSY`，当前中文消息为：

> 项目中有任务正在排队或执行，暂时无法归档或删除项目。请等待完成或先停止所有任务。

错误处理按 `error.code` 判断；用户提示展示本地化后的原因和处理方式，不只显示“删除失败”或“409”。服务端沿用现有语言解析规则，优先使用已保存的用户语言，其次使用 `Accept-Language`，支持中文和英文。

## 客户端交互

1. 删除前展示确认框。删除项目时说明仅空项目可删除，并提供归档建议；删除任务说明该会话和附件无法恢复，工作目录中的文件保留。
2. 已知任务正在排队或执行时，禁用删除按钮，并直接显示：“任务正在排队或执行，暂时无法删除。请等待完成或先停止任务。”
3. 发起删除后，以服务端结果为准。确认期间状态可能变化；收到 `TASK_BUSY`、`PROJECT_TASKS_BUSY` 或 `PROJECT_HAS_TASKS` 时，显示具体原因，保留原数据。
4. 停止任务后，等待 `active_turn_id` 变为 `null` 再允许删除。仅收到停止请求回执或 `cancel_requested=true`，不代表任务已停止。停止协议见[任务 WebSocket 接入指南](project-task-websocket.md)。
5. 收到 204 后移除对应列表项；如果正在查看被删除的任务，则关闭对应会话。任务删除标记应拦截迟到的分页结果和会话事件，避免已删除项重新出现。同步规则见[项目和任务增量同步说明](project-task-incremental-sync.md)。

## 数据范围和版本规则

项目删除在同一事务中检查没有保留任务、删除空项目并记录同步删除事件。被拒绝时不执行部分删除。单任务删除不影响所属项目、其他任务或独立分支，分支已经复制的附件仍可读取。

删除保留服务端和客户端工作目录中的文件，包括自动分配的任务工作区，不回滚已执行工具的副作用，也不删除专家记忆。已归档任务仍可显式删除，已归档项目仍需为空；删除后的再次读取或再次删除返回 404。

删除接口不要求版本参数。项目编辑、归档或恢复，以及任务改名、归档或恢复，仍须传递 `expected_revision`；切换专家/行动模式还须提供 `expected_configuration_revision`。完整接口参考见 [API 文档](api.md)。
