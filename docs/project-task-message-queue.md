# 任务消息队列使用和接入说明

日期：2026 年 10 月 16 日。

「项目和任务」网页支持执行中继续发送消息，与普通会话采用相同的先进先出队列。每个任务最多保留十条待发消息；当前轮结束后，网页逐条发送，每条形成该任务的新轮次。图片、通用文件和文字都可以排队，无项目任务使用同一规则。

队列保存在当前页面内存中。服务端仍只允许一个活动轮次，REST 和 WebSocket 在任务忙时直接发送新消息仍返回 `TASK_BUSY`。其他客户端接入时，应自行保留待发消息并遵循下述状态和幂等规则。

## 网页操作

任务执行中，输入框仍可编辑，发送按钮显示为「排队」。点击按钮或按 Enter 将当前正文、已上传附件和本条执行设置加入队列，然后清空输入框。Shift+Enter 继续换行。附件上传未完成、上传失败或队列已满时，不加入队列，保留当前草稿。

队列按加入顺序展示。用户可以移除尚未发送的消息，也可以取回编辑。取回会将正文、附件和执行设置恢复到输入框；已有草稿时先确认是否覆盖。附件复用已上传的 ID，预览通过鉴权重新读取，无需重复上传。正在发送的队头不能移除或取回。

同一「项目和任务」页面中切换任务或项目，原队列继续属于原任务，发送目标不会随当前选择改变。新任务按钮清空当前任务的待发队列。成功删除任务或项目后，清理对应队列。

刷新、关闭页面或离开「项目和任务」页面会丢失尚未发送的队列；服务端已接收的轮次继续保留。未关联任务的附件仍按上传接口的有效期处理，见[任务通用附件接入说明](project-task-input-attachments.md)。

## 派发时机

网页先读取原任务，再订阅任务事件。仅当任务的 `active_turn_id` 为 `null`、任务未归档且账号仍有访问权限时，才能派发队头。每次实际发送前重新读取任务，核对任务和项目归属以及最新状态。

| 当前情况                                   | 队列行为                         |
| ------------------------------------------ | -------------------------------- |
| 已入执行队列或正在运行                     | 保留消息，等待当前轮结束         |
| 等待审批、问题回答或客户端动作             | 保留消息，继续处理原交互         |
| 暂停                                       | 保留消息，恢复原轮或停止后再继续 |
| 当前轮成功、失败或确认取消，且没有活动轮次 | 发送队头，收到接收回执后移除该项 |
| 新轮已接收                                 | 等待新轮结束，再发送下一条       |
| 页面不可见或浏览器离线                     | 暂停新的派发，恢复后重新读取状态 |
| 任务归档、删除、无权访问或归属不符         | 停止派发并保留错误提示           |

点击「停止」只取消当前轮。取消请求回执若仍有活动轮次，队列继续等待；收到当前轮结束的确认后再发送下一条。队列消息不会代替审批决定、问题回答或客户端动作结果，也不会自动恢复暂停的轮次。

## 消息内容和执行设置

入队时保存消息的 `request_id`、`prompt`、有序 `attachment_ids` 和显式 `options`，附件展示元数据一并保留。之后在输入框修改设置，只影响后续加入的消息。取回编辑后修改正文、附件或设置，再发送会生成新请求标识；保持原内容则继续复用原标识。

项目的配置仍在服务端接收新轮时读取。排队不创建或绑定专家，也不冻结整个项目配置。当前任务审批模式是任务级设置，仍按原审批接口更新；排队本身不授权任何操作。

## 发送失败和断线恢复

`TASK_BUSY` 表示其他请求抢先创建了活动轮次。保留队头，重新读取并等待较新的任务状态，不持续重发同一空闲快照。

其他发送错误或网络结果未知时，保留队头并停止自动派发，显示「重试发送」。用户显式重试时先读取任务，检查是否已有同一 `request_id` 的轮次：存在则确认已经接收并移除队头；不存在且任务空闲时，复用原请求标识和完全相同的消息再次发送。服务端幂等核对仍是防止重复执行的最终保障。

结果未知的消息仍可移除或取回编辑，但这些操作只改变本地待发队列。请求可能已被服务端接收，移除或取回不会撤销已接收的轮次；需要取消执行时，应读取任务并停止当前轮。

读取或订阅断线后的恢复只重建读取和订阅，不自动重发结果未知的写请求。手动重试失败或取消的历史轮次，也须等待待发队列处理完或先移除队列，避免插入其前面。

## 接口边界

队列继续使用现有接口，没有新增服务端排队端点或数据库记录：

| 操作                   | 接口                                         |
| ---------------------- | -------------------------------------------- |
| 读取任务状态及近期轮次 | `GET /api/project-tasks/{task_id}`           |
| 接收任务变化           | 现有任务事件订阅                             |
| 发送队头               | `POST /api/project-tasks/{task_id}/messages` |
| 上传及读取输入附件     | `/api/project-tasks/attachments`             |

消息成功接收返回 `202 Accepted` 和 `TaskDetail`，表示轮次已持久化进入服务端执行队列。网页待发队列和该轮的执行排队状态具有不同生命周期：前者尚未向服务端提交，后者已经保存，运行结果以服务端轮次状态为准。

接口字段、鉴权和事件订阅详见[API 文档](api.md)、[任务 WebSocket 接入指南](project-task-websocket.md)和[任务通用附件接入说明](project-task-input-attachments.md)。
