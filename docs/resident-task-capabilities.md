# 私人助手与任务能力对照

本清单对应 2026-10-28 的实现。私人助手复用任务的内置网络搜索、附件上传和成果下载链路，并提供仅限本会话上传文件的只读工具；不会因此启用任意文件访问、命令、MCP、插件或设备执行权限。以下普通任务能力以 Octop 引擎为准；ACP 等外部引擎的搜索、工具与视觉能力由引擎声明和管理。

| 能力 | 私人助手 | 普通任务 |
| --- | --- | --- |
| 多轮交流 | 用户固定的私人身份与常驻会话 | 每个任务独立多轮，可关联项目及专家 |
| 内置网络搜索 | 新受理轮次默认可用，复用已配置的搜索服务及免配置搜索；已受理旧轮次保留原能力 | 默认开启，可通过任务的网络搜索开关关闭；每轮固定发送时的值 |
| 上传图片识图 | 支持选图、粘贴、图文和仅图片输入；沿用任务的图片校验和模型入参转换 | 支持相同的图片输入链路 |
| 图片限制 | 每条附件合计最多 9 个，每个不超过 25 MiB 及服务端上传限制；图片支持 JPEG、PNG、WebP、GIF，模型须支持视觉 | 同一限制 |
| 图片历史与追问 | 原发送回执、快照及历史保留附件；模型上下文保留图片引用 | 任务详情、历史与模型上下文保留图片引用 |
| 上传普通文件 | 支持选择、粘贴、仅文件及混合输入；回执与历史保留附件，可鉴权下载 | 可上传普通文件并在任务工作空间读取 |
| 读取附件内容 | 专用只读工具按附件 ID 读取本会话文件；支持文本、PDF、Word、Excel、PowerPoint 等可提取文字的文档，无 OCR | 通过任务文件工具、依赖与执行能力处理文件，具体格式取决于任务环境 |
| 返回文件给用户 | 委派任务发布真实成果后，私人会话及历史直接展示下载按钮 | 发布成果附件并提供鉴权下载；每轮最多 5 个、合计 50 MiB，单个最多 25 MiB |
| 搜索与网络权限 | 搜索工具可用不代表放开浏览器、任意网页读取或命令网络访问 | 搜索开关只控制内置搜索工具，不是网络隔离开关 |
| 浏览器操作 | 通过有相应能力的委派任务处理 | 工作台声明浏览器能力时可用 |
| 任意读写文件、运行命令 | 私人会话不直接开放，按需要委派任务；上传附件只读工具不扩大此权限 | 根据 ask/plan/craft 模式、目标目录和审批策略执行 |
| Skill、MCP、插件 | 可通过明确的任务范围交给委派任务，私人会话不直接加载 | 根据项目及专家的资源配置与本轮选项加载 |
| 知识库检索 | 仅使用本轮明确选择且仍有权限的知识库 | 按所选专家、本轮选择与默认开放库策略使用 |
| 长期记忆 | 独立私人事实管理；原始采集需开启，候选需确认 | 按任务与所选专家配置使用记忆，与私人助手记忆分别管理 |
| 子代理、团队 | 需要时交给配置了协作能力的委派任务 | 可选择子代理或专家团队 |
| 项目与工作目录 | 持续会话不因项目切换而更换身份；任务范围可明确选择项目 | 使用项目目录；未选项目时使用任务独立空间 |
| 用户电脑工具 | 私人会话不直接执行；委派任务只能使用用户明确选择的能力 | 使用客户端实际声明并授权的工具，目录路径本身不授予权限 |
| 模型选择 | 受理时解析私人实例、用户或全局模型偏好，保存本轮模型快照 | 可明确选择任务/本轮模型，按配置路由与故障切换 |
| 执行引擎 | 私人对话使用 Octop；专业工作交给普通任务 | Octop 或已配置、就绪且声明相应能力的 ACP 引擎 |
| 进展与成果 | 正文实时更新，委派任务通过关联收据回报实际结果及可下载文件 | 工具动作、计划、审批及成果附件均由任务保存和展示 |
| 取消与恢复 | 可取消指定轮次；断线查原请求，已中断轮次用新消息继续 | 可停止、重试，并按引擎能力暂停或从检查点继续 |
| 分支与并行工作记录 | 保持同一私人会话，独立工作通过任务关联 | 支持任务分支与独立任务 |
| 提醒与主动跟进 | 独立授权提醒、关注任务或定时创建任务，回到原会话 | 可由 cron 等入口创建和执行，结果可回流私人助手 |

## 搜索与双向附件的接入约定

客户端先读取 `GET /api/agents/resident-capabilities`：`message_types` 包含 `image` 表示图片输入已接入，包含 `file` 表示普通文件输入已接入，`web_search=true` 表示新消息可使用内置搜索。具体搜索服务仍取决于服务端配置；工具真实返回结果后才能据此回答。

图片和普通文件上传复用 `POST /api/project-tasks/attachments`，预览或下载复用 `GET /api/project-tasks/attachments/{attachment_id}`。这两个接口校验当前账号，不在客户端直接拼主机路径或使用未鉴权附件地址。

向私人助手发送：

```json
{
  "request_id": "stable-image-send",
  "prompt": "看看这张截图有什么问题",
  "attachment_ids": ["input_example"]
}
```

仅附件消息可省略 `prompt` 或传空字符串。服务端在消息受理时绑定附件，保存原附件 ID，并将元数据通过 `ResidentTurn.attachments` 返回；`authorization` 仍只表示额外选择的主机工具范围。相同 `request_id` 的重试须保留同一正文、附件顺序和授权，改变输入会冲突。私人会话附件不会自动授予或扩大委派任务的附件、项目及设备范围。

模型请求临时把图片引用展开为字节；持久会话保存引用，不把 base64 图片复制进正文或日志。历史保留不意味着模型在显式上下文整理后仍保留所有原图；普通任务另有图片重读工具，私人助手当前可重新上传图片进行查看。

普通文件通过 `resident_read_attachment` 按 ID 分页读取，工具只接受当前账号、当前私人会话已绑定的普通附件。省略 ID 可分页列出附件元数据；不接受主机路径。文档解析不执行文件内容，也不将附件视为授权；二进制、不支持或无可提取文字的文档会明确返回无法读取。普通文件无需视觉模型。

附件执行依赖统一 Task worker，正式服务器默认安装该 worker。未安装 worker 的旧 Gateway 兼容运行态明确拒绝附件输入及已有附件会话的继续执行，避免静默丢失附件上下文。

返回文件复用委派任务回报的 `artifacts` 元数据。客户端使用回报中的 `task_id` 和 `artifact_id` 调用 `GET /api/project-tasks/{task_id}/artifacts/{artifact_id}/download`，不使用文件路径或任意 URL；服务端仍校验当前账号和文件完整性。回报与文件引用进入私人历史和模型上下文，只有实际发布的成果才显示下载入口。若原任务或文件已删除，历史记录仍可能存在，但下载会失败。

本次没有修改 Swift/App 页面，也没有增加私人会话直接生成图片的工具。App 可按上述现有 `/api` 契约接入；Dashboard 已接图片与文件选择、粘贴、历史附件和成果下载。
